## 首次导入微信开发者工具的编译报错修复 + 全量 review

**根因**：`pages/today/today.wxml` 第 8 行插值少写一个 `}`——
`切换繁体 ({{lang === 'zh-Hans' ? '简体' : '繁体'})` 只有 1 个 `}`。
WXML tokenizer 一直往下找 `}}`，把 `</button>` 吞掉，直到第 12 行 `{{poem}}` 才闭合，
于是解析器认为 button 未关闭 → 报 `expect end-tag button, near text`（报错位置具有误导性，真正原因在上文）。

**排查方法（可复用）**：对 `pages/*/*.wxml` 跑一遍「`{{` … `}}` 配对 + 标签栈平衡」脚本，
比肉眼定位快得多。WXML 编译报 "expect end-tag X" 时优先怀疑上文的 `{{ }}` 不配对。

**已修**：
- today.wxml 第 8 行补齐 `}}`，顺带修正按钮文案（原逻辑恒显示「切换繁体 (简体)」，语义矛盾）
- utils/api.js：`path` 被一起塞进 query string（现在 buildQuery 跳过 path）
- utils/api.js：移除 `URLSearchParams`（小程序逻辑层 Android V8 无此 Web API，真机会崩），改手写 encodeURIComponent
- utils/api.js：normPoem 的 `lines` 在 content 非数组时由 null 改为按 `\n` 切分
- settings：测试结果样式用 `testResult[0]==='连'` 判断成败——「连接成功」和「连接失败」首字都是「连」，恒为绿色，已改为 `testOk` 布尔字段
- search.js：移除未使用的 `stats` 导入

## 第二轮：按 review 建议落地 5 项改进

- **今日一诗真缓存**（today.js 重写）：storage 键改为按语言分键 `poetry_today_${lang}`；
  `pick(auto)` 用参数区分「今日那首」与手动「再抽一首」，只有 auto 才写缓存。
  onShow 顺序很关键：先判断「本次会话已有诗 && 语言未变 → 不动」（保留用户正在看的，
  手动抽的诗切 tab 回来不会被缓存顶掉），再查当天缓存，最后才发请求。
  日期用本地时间拼，**不能用 toISOString**（UTC 会让东八区早 8 点前算成前一天）。
- **首屏白闪**：today.wxml 占位块条件由 `!poem && !loading && !error` 简化为 `!poem`，
  loading 期间占位块保持显示（按钮转圈），不再有空白帧；toggleLang 不清 poem，新诗回来直接替换。
- **详情传参**：新增 `utils/nav.js` 的 `gotoPoem(p)`——始终写 `globalData.pendingPoem`，
  同时短诗（编码后 ≤1000 字符）仍带 `?p=` 参数以保住微信搜一搜抓取；长诗只走缓存避免 URL 截断。
  poem.js onLoad 优先读缓存、读完清空、查不到再退回 `opt.p`。
- **域名**：config.js 补充后台配置 request 合法域名的完整路径与注意事项；
  `project.private.config.json` 的 `setting.urlCheck` 已是 false（本地不校验域名）。
- **基础库**：`project.config.json` 的 libVersion 3.4.0 → 3.17.4，与实际调试环境对齐。

**验证手法（可复用）**：用 node 写个 harness，mock 全局 `Page` / `getApp` / `wx`
（注意 `getApp()` 必须返回**同一个单例对象**，否则 globalData 状态每次都丢），
直接 require 页面的 .js 驱动 onShow/pick/toggleLang，断言请求次数与缓存内容。
比在开发者工具里手点快，且能覆盖「切 tab / 切语言 / 改设置后返回」这些分支。

## 第三轮：UI / 交互整体重做（现代极简浅色）

原来的深色 UI 被判定「丑、布局不合理、没有图标」，按 impeccable + apple-design 两个技能
的规范整体重做。设计系统细节见 MEMORY.md。

**图标**：环境无 Pillow，手写了 `png` 编码器（zlib + struct）配合距离场 SDF 光栅化
（4x4 超采样抗锯齿），生成 4 个 tabBar 图标 × 选中/未选中。
两个关键坑：
- `sd_rr`（圆角矩形）返回的是**带符号**距离，描边判断必须 `abs(sd) <= w/2`，
  只写 `sd <= w/2` 会把整个矩形填满（当时日历图标就糊成了一块实心方块）。
- 验证要在**真机尺寸**下做：tabBar 图标文件是 81×81，实际只显示约 27px。
  直接把 27 当画布光栅化会只画出图标左上角（坐标系还是 0–81）；
  正确做法是 81×81 渲染后按 3×3 盒式降采样到 27×27 再放大看。

**视觉验证**：把 WXSS 按 `1rpx = 0.5px` 转成 CSS，复刻页面结构生成 HTML，
用 Chrome headless 截图回看。三个坑：
- `page` 选择器上定义的 CSS 变量在预览 HTML 里不存在，必须把同名变量也挂到容器上，
  否则所有 `var()` 失效、卡片会整个塌掉（看起来像样式全丢了）。
- 截图要禁用入场动画（`.rise/.rise-item { animation: none }`），否则会拍到半透明的中间帧。
- `--force-device-scale-factor=2` 让文字清晰。

预览产物归档在 `.workbuddy/design-preview/`，并在 `project.config.json` 的
`packOptions.ignore` 里排除了 `.workbuddy`，避免被打进小程序包。
